# CRM 权限配置与验收

PM-6 首个交付覆盖客户、联系人、负责人选择及销售团队维护。销售只访问本人负责的客户；经理必须同时拥有经理业务权限与有效团队经理归属，才能访问该团队有效成员负责的客户；现有 root 管理员访问全部。联系人继承客户范围。团队和成员停用而不删除，转组后客户范围随负责人当前归属变化。

商机、跟进、看板与统计等待 PM-3/4/5 接入，不在此版本中宣称已提供。客户转移不改写未来商机负责人。跨团队客户转移只允许管理员，目前只影响客户及其联系人。

## 初始化

在更新后的应用运行数据库迁移/seed：

```sh
pnpm nocobase db apply
```

新迁移创建 `crmTeams`、`crmTeamMembers`、`crmTeamChanges`。成员的 `userId` 唯一；团队和成员维护记录操作者、时间与版本，并在同一事务写入审计。seed 仅创建不存在的 `crm.sales`、`crm.salesManager` 权限集；不覆盖管理员已有配置，不分配账号，不创建用户或密码。现有客户迁移保持不变。

首次启动和既有安装都须由管理员检查实际权限集内容。若键已经存在，seed 保留其原有内容，管理员应按下面的矩阵配置。数据库回退会删除团队与审计表，属于数据删除，使用前先备份并按部署流程审阅。

## 网页配置（Super Admin）

以下路径均相对目标 CRM 应用挂载路径；Studio 自身角色不能替代这些配置。

1. 设置 › 权限管理 › 权限集（`/settings/authorization/permission-sets`）检查 `crm.sales` 与 `crm.salesManager`。
2. 设置 › 用户（`/settings/users`）为已有启用账号分配对应权限集。不得给普通销售额外 root、经理、全量业务权限或扩大范围的默认/共享规则。
3. 设置 › 销售团队（`/settings/crm-teams`）创建团队，选择用户并维护单团队归属与销售/经理职责。此页面仅现有 root 管理员可用，不会自动分配业务权限。经理职责与权限集不一致时显示提示。
4. 设置 › 权限管理 › 检查器（`/settings/authorization/inspector`）检查账号的直接与继承来源；撤销权限时检查所有来源。

| 项目                             | 销售                                | 销售经理        |
| -------------------------------- | ----------------------------------- | --------------- |
| 页面 `customers/access`          | 允许                                | 允许            |
| `crm.customers` view/create/edit | `recordAccess.recordsIOwn`，ownerId | `crm.myTeam`    |
| `crm.customers` transfer         | 不授予                              | `crm.myTeam`    |
| `crm.contacts` view/create/edit  | `crm.parentOwned`                   | `crm.myTeam`    |
| `crm.customerOwners` view        | `crm.selfUser`                      | `crm.teamUsers` |

页面与业务动作独立；只有页面不能调用 API，只有动作不能打开页面。正向权限来源会合并；此版本没有添加全量 Default access 或 Sharing rules。经理没有有效经理成员关系时返回空范围，不能退回全量。销售无团队仍可访问本人客户。

普通编辑拒绝 `ownerId`，转移须使用独立动作并校验记录范围、有效目标账号与版本。越界记录和不存在记录统一返回 404，无业务动作返回 403，无会话返回 401。列表 total、重复名称提示、联系人和选择器均在数据库策略内查询。外部过滤参数不能扩大范围。

停用团队/成员或转组时页面先确认影响；提交后通知权限服务使客户端授权与业务缓存失效。使用版本检查拒绝陈旧保存，审计与业务修改整体回滚。当前自动回归使用 SQLite；其他数据库方言及并发转组中的隔离行为须在相应部署环境补验。

## 验收

测试应用准备两个团队、销售 A/B/C、本团队经理 M 和管理员，全部使用虚构业务记录。检查 A 仅见本人客户与联系人，不能请求 B/C 详情、修改负责人或关联越界联系人；M 仅见团队客户、总数及负责人候选，可以团队内转移；管理员可以跨团队转移。再验证转组、停用团队/成员/账号、撤销全部权限来源后的新请求，陈旧版本冲突与回滚。

代码回归在 `tests/logic/crm-permissions.test.ts` 和 `crm-teams-migration.test.ts`，页面回归在 `tests/components/crm-teams.test.tsx`、客户组件测试和 `tests/playwright/crm-permissions.test.ts`。浏览器回归使用独立数据库与临时测试账号，覆盖普通销售登录、经理转移、中文/英文、暗色/亮色、375px 及中文组合输入；截图不含真实业务数据、会话或个人账号资料。

Super Admin 仍需在实际目标测试应用使用已配置普通销售账号登录一次，记录应用 URL、版本、角色、虚构场景和允许/拒绝结果，并补齐经理/管理员边界证据。自动化临时应用不能替代这次人工验收。PM-7 承接实际团队维护配置，PM-8 承接完整业务接入及验收；PM-6 不因此标记 done。
